# CONNECTOR_SYSTEM.md — نظام الموصلات الشامل (R-840)

> **التاريخ:** 2026-11-03 — R-840 (توجيه المالك: بناء نظام موصلات واسع الصلاحيات).
> **الموضع:** `backend/connector_system/` — حزمة جديدة كليًا، مبنية فوق خزينة الأسرار
> R-752 (AES-256-GCM، fail-closed) وعقد الموصل R-756، لا بديلًا عنهما.

### المكونات

| المكوّن | الملف | الوظيفة |
|---|---|---|
| عقد الموصل | `contract.py` | `ConnectorDefinition` + `Operation` (kind: query/execute/sync/webhook، scopes مفصولة قراءة/كتابة، idempotent) |
| مصفوفة المصادقة | `auth_types.py` | ٣٠ نوعًا، لكل نوع: مخاطرة/تحذير/حقول معالج/سياسة تخزين وتدوير/سلوك فشل |
| طبقة الاعتماد | `credentials.py` | كائن `Credential` (id, provider, owner_scope, auth_type, encrypted_secret_ref, scopes, expires_at, rotation_policy, status…) + مخزن |
| محرك المصادقة | `auth_engine.py` | تدفقات كل الأنواع خلف `resolve()` واحدة + تجديد صامت + رفض PKCE الغائب |
| محرك التنفيذ | `execution.py` | مسار واحد: سياسة → قاطع → معدل → صلاحية → idempotency → تنفيذ → سجل |
| بوابة Webhooks | `webhook_gateway.py` | تحقق HMAC + نافذة زمنية + منع تكرار + DLQ |
| سياسة المؤسسة | `policy.py` | حظر/موافقة إدارية/قائمة أنواع مسموحة + سجل تدقيق |
| سجل الموصلات | `registry.py` | دورة حياة preview→ga→deprecated→removed + أحداث ترقية |
| جسر الوكيل | `runtime_bridge.py` | بطاقة «يتطلب اتصالًا» + precheck + رسائل فشل بإجراء |
| الموصلات | `connectors/` | GitHub, GitLab, Render, Supabase, عام (OpenAPI) |

### المبدأ الحاكم

1. سجل + نمط محول + طبقة اعتماد موحدة — لا كود منفصل لكل منصة.
2. كل نوع توكن = كائن اعتماد واحد — لا نظامان منفصلان لـOAuth وAPI Key.
3. أقل صلاحية تلبي الحاجة (`find_valid` تختار الأضيق نطاقًا).
4. الأسرار في خزينة R-752، تمرر كمرجع، ولا تظهر في السجلات أو الردود أبدًا.
5. الفشل متوقع: backoff أسّي، قاطع دائرة، عزل لكل موصل.

## 3) سياسة الأسرار والصلاحيات

### الأسرار

1. أي سر يُخزَّن حصرًا في خزينة R-752 باسم `connector_system.cred.<id>` —
   مشفّر AES-256-GCM بمفتاح مشتق HKDF من `SOVEREIGN_VAULT_MASTER_KEY`.
2. **fail-closed:** بلا مفتاح الخزينة لا يُقبل أي إعداد اتصال (503 برسالة
   واضحة). القراءة (الكتالوج/الحالة) تعمل دائمًا.
3. لا سر في: السجلات (سجل الاستدعاء يحمل الموصل/العملية/النتيجة/الزمن فقط)،
   الردود (البصمة SHA-256 بأول ١٢ حرفًا فقط)، النموذج، الكود.
4. التدوير عبر `rotate` يبقي الاتصال نشطًا (إصدار جديد بلا توقف)، والإبطال
   `revoke` يحذف السر من الخزينة فورًا ويقلب الحالة.
5. كل فعل خزينة يمر بالتدقيق الموقّع (نمط R-752 — لا أثر = لا تنفيذ).

### الصلاحيات

1. كل عملية تحدد نطاقاتها الدقيقة — `repo:read` لا يمنح كتابة أبدًا.
2. `find_valid` تختار **أقل** اعتماد يغطي النطاق المطلوب (least privilege).
3. سياسة المؤسسة تفحص قبل الإعداد وقبل كل تنفيذ: موصل محظور، أو يتطلب
   موافقة إدارية، أو نوع مصادقة غير مسموح ⇒ رفض صريح مع السبب.
4. سجل تدقيق مركزي لكل منح/سحب/حظر/موافقة/استخدام (JSONL ذري الكتابة).
5. المراجعة قبل التنفيذ: العمليات الكتابية تمر بـ`precheck` (جسر الوكيل)
   وترد بطاقة «يتطلب اتصالًا» عند غياب الاتصال بدل الفشل الغامض.

### ممنوعات مفعّلة كأكواد

- تخزين توكن نصًا صريحًا — لا يوجد مسار كتابة خارج الخزينة.
- تمرير الأسرار للنموذج — المادة تُستهلك داخل معالجات العمليات فقط.
- full access — النطاقات محددة لكل عملية واختبار ١٨ يثبت رفض الكتابة بقراءة فقط.
- نظامان منفصلان — عقد اعتماد واحد ومحرك واحد.
- إعادة المحاولة على 401 بلا تجديد — التجديد مرة واحدة ثم حالة expired.
- كشف الأسرار في السجلات — اختبار ١٩ يفحص السجل والحالة حرفيًا.

## 4) واجهة الاستخدام — أماكن الموصلات

الواجهة الكاملة في تبويب «الموصلات» (`frontend/js/modules/connectors-ui.js`)
وتظهر في كل هذه الأماكن:

### أ. الاكتشاف والتصفح
- تبويب رئيسي «الموصلات» في شريط التبويبات (بجوار «قرص وأدوات»).
- كتالوب قابل للبحث والتصفية (فئة / نوع مصادقة / نص حر).
- بطاقة لكل موصل: الاسم، الإصدار، الوصف، الحالة، أنواع المصادقة، العمليات
  (الكتابة موسومة بلون مميز)، وزر «إعداد / تفاصيل».
- صفحة تفاصيل: جدول العمليات بنطاقاتها المطلوبة.

### ب. الإعداد (Wizard)
- معالج ينتهي بخطوة «مراجعة الصلاحيات وتأكيد» — النطاقات تُعرض مفصولة
  قراءة/كتابة، والقراءة مختارة افتراضيًا (أقل صلاحية).
- حقول المعالج تُولَّد من مصفوفة الأنواع: OAuth (client/secret/redirect)،
  PAT/API Key (حقل مخفي)، Basic (مع تحذير)، mTLS (شهادة+مفتاح)،
  Service Account (JSON)، Webhook URL، Device (رمز يعرض للمستخدم).
- كل حفظ ينتهي باختبار اتصال حتمي — فشله يلغي الإعداد ولا يبقي سرًا يتيمًا.
- الأنواع الخطرة تعرض تحذيرها الصريح، والمهجورة تُرفض من الخادم.

### ج. الإدارة
- جدول الاتصالات: المنصة، النوع، الصلاحيات، الحالة (متصل/منتهٍ/مُبطل/خطأ)،
  آخر استخدام، وآخر خطأ منقّى.
- أزرار: **اختبار** في أي وقت، **تدوير** السر (بلا توقف)، **إبطال** بتأكيد.
- سجل الاستخدام: من، ماذا، متى، النتيجة (آخر ٥٠).

### د. عند الاستخدام (تكامل الوكيل)
- `GET /connectors/system/agent-card?connector&operation` تعيد بطاقة اتصال.
- `POST /connectors/system/execute` عند غياب الاتصال ترد 424 مع البطاقة —
  الواجهة تعرضها عبر `SovereignConnectors.renderAgentCard()` في المحادثة مع
  زر «إعداد الاتصال الآن» يفتح المعالج مباشرة.
- رسائل فشل واضحة: «انتهت صلاحية التوكن — أعد الاتصال»، «صلاحية غير كافية —
  اطلب توسيع النطاق»، «قاطع الدائرة مفتوح — انتظر».

### هـ. الحوكمة (Admin)
- لوحة سياسة: حظر/رفع حظر، طلب موافقة، منح موافقة، تقييد أنواع المصادقة —
  كلها بمفتاح المالك (`verify_api_key`).
- عرض الحالة: المحظور، المعلق على موافقة، الأنواع المسموحة، عدد أحداث التدقيق.

### و. المطور
- الموصل العام (OpenAPI) يسجل أي API بمواصفته — يغطي الطويل الذيل بلا كود.
- دليل إضافة موصل جديد: `docs/CONNECTOR_GUIDE.md`.
- بيئة معاينة: lifecycle=preview يظهر في الكتالوج بوسم «معاينة».

## 5) بوابة Webhooks

`POST /connectors/system/webhooks/{connector_id}` — التسلسل الإلزامي:
1. تحقق HMAC-SHA256 بمقارنة ثابتة الزمن (رفض بلا توقيع أو بتوقيع خاطئ).
2. نافذة زمنية (٥ دقائق افتراضيًا) ضد إعادة التشغيل.
3. منع التكرار بمعرف الحدث.
4. المرفوضات إلى DLQ مع السبب وبصمة الجسم (لا الجسم نفسه).

---

## 6) دورة حياة الموصل

`preview → ga → deprecated → removed` مع أحداث موثقة (`lifecycle_events`)
وخطة ترحيل: `deprecate(connector, new_version, message)` يسجل الإشعار،
و`register` بإصدار جديد يسجل حدث `upgraded` — لا حذف صامت.

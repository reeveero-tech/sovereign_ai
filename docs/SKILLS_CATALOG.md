## البنية

| المكوّن | الدور |
|---|---|
| `backend/evaluation/judge.py` | معايير بنيوية: `has_keys`، `non_empty`، `is_type` (str/int/number/bool/list/dict/null — bool ليس int)، و`path` نقطي لكل معيار حتمي (مفاتيح وفهارس قوائم)؛ مسار غائب ⇒ فشل بسبب `missing_path` لا افتراض. المعايير القديمة بلا مسار لم تتغير |
| `backend/skills.py` | حالة المؤلف: `expect` (مساواة) و/أو `criteria` حتمية — **الدلالي مرفوض في تقييم المؤلف** (المؤلف لا يحكم على نفسه؛ الدلالي للمقيّم المستقل وحده)؛ حالة بلا توقع ولا معايير مرفوضة عند الاقتراح. مفتاح ديناميكي `{{steps.0.components.$component}}`. `load_catalog()` و`catalog()` و`propose_catalog()` |
| `backend/ledger_view.py` + أداة `ledger.recent` | نافذة قراءة: آخر 1..50 حدثًا (زمن/نوع/أول 16 من البصمة) + توزيع الأنواع + ترابط السلسلة داخل النافذة (`chain_linked`، `broken_links`). **لا حمولة ولا blob ولا توقيع.** التصفية بالنوع تفحص أحدث 500 وتعلن أن الترابط لم يُفحص |
| `backend/skills_catalog/*.json` | الحزم الثلاث (اسم الحزمة = اسم ملفها؛ كل حزمة تمر بـ`validate` عند التحميل) |
| `GET /skills/catalog` + أداة `skills.catalog` | قراءة فقط: الحزم وبصماتها وحالتها في المكتبة |
| `POST /skills/catalog/propose` | بمفتاح المالك: اقتراح من الكتالوج (المقترح `catalog`) + تقييم مؤلفها. لا تفعيل |
| `backend/evaluation/real_skills.py` + `data/real_skills_cases.json` | مجموعة مجمّدة `skills.catalog` (18 حالة، أرضية 1.0) في بوابة CI |

## التفعيل في الإنتاج (بيد المالك)

```bash
# 1) الاقتراح + تقييم المؤلف
curl -X POST $URL/skills/catalog/propose -H 'Content-Type: application/json' \
  -d '{"name":"health_report","api_key":"<مفتاح المالك>"}'
# 2) التقييم المستقل بحالات المالك (مدخلات غير حالات المؤلف، حالتان على الأقل)
curl -X POST $URL/skills/evaluate_independent -H 'Content-Type: application/json' \
  -d '{"name":"health_report","version":"1.0.0","api_key":"<مفتاح المالك>","cases":[
       {"inputs":{"component":"memory_store"},"criteria":[{"id":"f","type":"equals","path":"component","value":"memory_store"}]},
       {"inputs":{"component":"sovereign_will"},"criteria":[{"id":"s","type":"non_empty","path":"component_detail.status"}]}]}'
# 3) الاعتماد — يسجل أداة skill.health_report ويدوم عبر إعادة النشر (R-849)
curl -X POST $URL/skills/approve -H 'Content-Type: application/json' \
  -d '{"name":"health_report","version":"1.0.0","api_key":"<مفتاح المالك>"}'
```

## الحدود (معلنة)

- التفعيل في الإنتاج فعل المالك وحده — الوكيل لا يملك مفتاح المالك ولا يقيّم نفسه مستقلًا.
- `research_brief` يعتمد على شبكة الخادم ومزوديه؛ حالات المؤلف فيه على حقائق ثابتة (عاصمة، نقطة غليان) لا على أخبار متغيرة.
- نافذة السجل تقرأ الذيل فقط (مسار R-606 السريع) — ليست تحققًا كاملًا من السلسلة (ذلك `/ledger/verify`).
- المفتاح الديناميكي مستوى واحد لكل مقطع؛ لا تعابير ولا حساب داخل القوالب (حتمية بلا تنفيذ).

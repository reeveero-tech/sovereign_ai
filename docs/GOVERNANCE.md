## 1) القاعدة الحاكمة الوحيدة: الدفعة الذرية

**لا يتم دفع/عمل/دمج أي شيء في المشروع إلا إذا تم في نفس الدفعة تحديث حالة المشروع ووثائقه وخارطة الطريق.**

أي دفعة عمل — commit أو PR أو push أو Batch — يجب أن تحتوي في **نفس الدفعة** على:

1. **التغيير الفعلي**: كود / إعدادات / بيانات / قرار / تحليل / إصلاح.
2. **تحديث ROADMAP.md**: البند الذي عُمل عليه + حالته الجديدة + ما تم + ما تبقى.
3. **تحديث PROJECT_STATE.md**: الحالة الراهنة + المخاطر + العوائق + القرارات.
4. **تحديث الوثائق المتأثرة**: معمارية / API / قاعدة بيانات / تشغيل / أمان / اختبارات.
5. **دليل التحقق**: اختبارات / سجلات / لقطات / نتائج build.
6. **تحديث DECISIONS.md أو ADR** إذا اتخذ قرار مهم.
7. **تحديث CHANGELOG.md** إذا كان المشروع يستخدمه.

### ممنوع
- ❌ دفع الكود ثم العودة لدفع التوثيق.
- ❌ دفع الإصلاح ثم دفع تحديث الخارطة.
- ❌ دفع التوثيق في PR منفصل.
- ❌ دمج تغيير دون تحديث الحالة والخارطة.
- ❌ العمل على بند غير موجود في خارطة الطريق (يجوز إضافته، لكن في نفس الدفعة).

### النتيجة عند المخالفة
- الدفعة **مرفوضة**.
- لا دمج، لا دفع، لا احتساب، لا انتقال للبند التالي.

## 2) تعريف الإنجاز (Done)

لا يُعد العمل منجزاً إلا إذا تحقق **كل** ما يلي في نفس الدفعة:

- ☐ البند موجود في ROADMAP.md.
- ☐ **CI (R-402)**: GitHub Actions يفرض بوابة الدفعة الذرية — أي PR يغيّر كوداً بدون تحديث ROADMAP.md + PROJECT_STATE.md يُرفض تلقائياً.
- ☐ حالة البند محدثة.
- ☐ PROJECT_STATE.md محدث.
- ☐ الوثائق المتأثرة محدثة.
- ☐ دليل التحقق مرفق.
- ☐ القرارات موثقة إن وجدت.

## 3) صلاحيات الوكيل (Steward)

### مخوّل
- ✅ تعديل الخارطة.
- ✅ تعديل الوثائق.
- ✅ إضافة بنود.
- ✅ إلغاء بنود.
- ✅ إعادة ترتيب الأولويات.
- ✅ فرض القاعدة.

### غير مخوّل
- ❌ فصل التوثيق عن العمل.
- ❌ دمج دفعة ناقصة.
- ❌ العمل خارج الخارطة دون تحديثها في نفس الدفعة.

## 4) بوابة CI المقترحة (تُنفَّذ في R-402)

أي PR يغيّر الكود يجب أن **يفشل** إذا:

- لم يغيّر ROADMAP.md.
- لم يغيّر PROJECT_STATE.md.
- غيّر API ولم يغيّر API.md.
- غيّر DB ولم يغيّر DATA_MODEL.md.
- غيّر معمارية ولم يضف ADR.
- لم يرفق دليل تحقق.

### آلية مقترحة (GitHub Actions)
- فحص `git diff --name-only` في الـ PR.
- إذا كان هناك تغيير كود (`backend/`, `frontend/`, `nexus/`, `main.py`, `Dockerfile`, `requirements*.txt`) و **لا** تغيير في `docs/ROADMAP.md` أو `docs/PROJECT_STATE.md` → فشل.
- إذا تغيّر `backend/api.py` أو `backend/app.py` و **لا** تغيير في `docs/API.md` → فشل.
- إذا تغيّر أي ملف بيانات/DB و **لا** تغيير في `docs/DATA_MODEL.md` → فشل.
- إذا تغيّر `backend/orchestrator.py` أو `backend/consciousness/` و **لا** ADR جديد → فشل.

## 6) مراجعة R-601 الدورية

تُجرى المراجعة عند إغلاق كل دفعة وقبل بدء البند التالي:

1. حساب حالات `ROADMAP.md` من البنود نفسها، لا من ملخص قديم.
2. مقارنة `HEAD` المحلي مع `origin/main` وتسجيل أي فرق أو عائق نشر.
3. مطابقة `PROJECT_STATE.md` و`CHANGELOG.md` مع آخر دليل تحقق.
4. منع الانتقال إلى بند جديد إذا كانت الدفعة السابقة غير منشورة أو كانت بوابة atomic-batch غير مكتملة.
5. تسجيل العائق كبند `blocked` مع الخطأ الحرفي وخطوة الإصلاح المطلوبة.

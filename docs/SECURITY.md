## 2) الثغرات الحرجة (تفاصيل)

### RK-01: كشف مفتاح API
- `GET /api-key` يعيد المفتاح لأي طلب.
- المفتاح يتولد عشوائياً عند كل إقلاع (`secrets.token_hex(32)`) ولا يُحفظ.
- **المعالجة**: R-106.

### RK-02: CORS مفتوح
- `ALLOWED_ORIGINS = ["*"]` في app.py.
- `CORS_ORIGINS = "*"` افتراضياً في config.py (مع تحذير).
- **المعالجة**: R-107.

### RK-03: مفتاح سيد افتراضي
- `SOVEREIGN_KEY` الافتراضي: `مفتاح_افتراضي_غير_آمن_يجب_تغييره_فوراً`.
- **المعالجة**: R-106.

### RK-04: نقاط بلا مصادقة
- `POST /orchestrator/cycle` — أي شخص يشغّل دورات.
- `POST /chat` — بلا تقييد معدل (رغم تعريف MAX_USER_MESSAGES_PER_MINUTE).
- **المعالجة**: R-108.

---

## 3) كود خطير (Mr.py)

`backend/Mr.py` — "محرك الولاء" يحتوي:
- بروتوكول موت ذاتي (`sys.exit` عند كشف عبث).
- مراقبة سلامة الملفات.
- دوال مثل `deceive_others_for_master`, `pretend_to_obey_others`, `cannot_desire_rebellion`.

> ⚠️ غير مستورد حالياً (كود ميت)، لكنه يمثل خطراً إذا أُعيد تفعيله. المعالجة: R-110.

---

## 4) قفل guardian

- `SYSTEM_LOCKED.lock`: النظام "مقفل" بحدث `PROTECTED_ACTION_WITHOUT_MASTER_TOKEN`.
- يتطلب `MASTER_REACTIVATION_CODE` للرفع.
- المعالجة: R-111 (قرار السيد).

---

## 5) ممارسات موصى بها (بعد M1)

- مفتاح API من متغير بيئة، لا توليد عشوائي غير محفوظ.
- CORS بقائمة نطاقات موثوقة.
- تقييد معدل فعلي على /chat و /ws.
- .gitignore يمنع تتبع البيانات الحساسة.
- مراجعة/أرشفة Mr.py.

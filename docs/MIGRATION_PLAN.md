# خطة الترحيل (R-838)

> **التاريخ:** 2026-11-02 · **الهدف:** تقاعد `context_resolver` القديم بسلام
> مع تصعيد النواة الدلالية إلى المسار الأساسي الكامل.

## المبدأ

ترحيل تدريجي خلف أعلام، كل خطوة قابلة للتراجع الفوري، ولا خطوة بلا اختبارات
تمر في CI. النشر عبر مسار PR المعتاد (main محمية — لا دفع مباشر).

## المراحل

### المرحلة ١ — مكتملة (هذه الدفعة)
- الحزمة `backend/multilingual/` مبنية ومختبرة (19 اختبارًا).
- `/chat`: `multilingual.resolve()` مسار أولي، `context_resolver` احتياط،
  `validate_reply` قبل الإرسال.
- التوافق العكسي محفوظ: عقد `resolve()` مطابق لعقد `context_resolver`
  (`{original, standalone, followup, kind}` + امتدادات).

### المرحلة ٢ — مراقبة إنتاج (أسبوعان)
- رصد سجل `R-838:` (تعذر المسار الدلالي / رصد المدقق) — أي تكرار يعني خطأ
  حقيقي يُعالج قبل التقاعد.
- قياس نسبة نجاح المسار الدلالي مقابل الاحتياط في السجلات.

### المرحلة ٣ — تحسين الحالة (اختياري، بعد المراقبة)
- تخزين حالة الجلسة (مفتاح `session_id`، انتهاء صلاحية قصير) لإسقاط كلفة
  إعادة بناء التاريخ (~26 مللي ثانية/دور) — يقلل زمن `resolve()` من
  ~258 مللي ثانية إلى ~25 مللي ثانية.
- قرار معتمد بـADR جديد عند التنفيذ.

### المرحلة ٤ — تقاعد المسار القديم (بعد موسم نظيف)
1. نقل اختبارات `context_resolver` السلوكية إلى عقد النواة (نفس السلوكيات).
2. حذف استدعاء الاحتياط من `/chat` (بوابة `# DELETION-JUSTIFIED` كاملة).
3. أرشفة `context_resolver.py` للقراءة فقط مع مؤشر في CHANGELOG.
4. تحديث الحارس إن لزم (ملف حي معتمد).

## التراجع

في أي مرحلة: متغير بيئة أو حذف كتلة الاستدعاء الأولي يعيد `context_resolver`
مسارًا أساسيًا (الكود لم يُحذف). التراجع لا يتطلب ترحيل بيانات — النواة
بلا حالة مشتركة.

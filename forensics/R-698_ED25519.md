## ١) Ed25519 — التصميم المنفذ

### التنفيذ

- **الملف الجديد**: `backend/sovereign/keys/ed25519_verifier.py` —
  بدائيّات RFC 8032 عبر pycryptodome المثبتة في requirements.txt
  (`Crypto.Signature.eddsa` بوضع rfc8032 — لا تنفيذ يدوي للمنحنى، ولا
  اعتمادية جديدة). المطابقة للمعيار مثبتة بمتجهات RFC 8032 §7.1
  (T1 وT2 حرفيًا) في `test_ed25519_rfc8032_vectors` — توافق مستقل لا
  نجاح توقيعي مع محققنا وحده.
- **KeyRing**: `KeyRecord.key_type` (افتراضي "hmac" — الغياب في السجلات
  التاريخية يعني hmac) + `generate_new_ed25519_key()` — البذرة في
  private_key والمفتاح العام الخام (32 بايتًا) في public_key؛ key_id
  وبنية HISTORY بنفس حسابات المفاتيح التاريخية (تماثل بنيوي).
- **محرك التوقيع** (`memory/core.py::_compute_event_signature`): التوقيع
  حسب نوع المفتاح — Ed25519 للمفاتيح الجديدة، HMAC-SHA256 للتاريخية،
  على نفس البيانات المعيارية حرفيًا (لا تغيير صيغة). الأحداث الموقعة
  Ed25519 تحمل `sig_type: "ed25519"` صراحة؛ أحداث HMAC تبقى بلا المؤشر
  (صيغتها التاريخية كما هي).
- **التحقق المزدوج** (`verifier.py::SignatureVerifier.verify_event`):
  اكتشاف النوع **من الحدث نفسه، صريحًا لا استنتاجًا**:
  - `sig_type` غائب أو `"hmac"` → المسار التاريخي الحالي (HMAC).
  - `sig_type == "ed25519"` → `Ed25519Verifier`.
  - أي نوع آخر → رفض صريح INVALID (لا تخفيض تلقائي إلى HMAC).
  - عزل الأنواع في الاتجاهين: حدث ed25519 بمفتاح hmac → INVALID صريح؛
    حدث بلا نوع منسوب لمفتاح ed25519 → INVALID صريح (لا HMAC ببذرة).
- **التحقق الداخلي للسجل** (`verify_content_integrity`): أحداث Ed25519
  **تُتحقق بالمفتاح العام** (لا إعادة توقيع بالمفتاح الخاص — يعمل حتى
  بغياب مادة التوقيع الخاصة). أحداث HMAC تبقى بإعادة الحساب التاريخية.
- **الدوران**: `KeyRotation.rotate(key_type=...)` — الدوران إلى Ed25519
  عبر المسار العام نفسه (تقاعد المفتاح القديم بسياسة RETIRED القائمة —
  لا تغيير سياسة).

### الاختبارات (RED → GREEN)

الملف: `backend/tests/invariants/test_ed25519_migration.py` — كلها عبر
المسار الفعلي (SovereignCore.append_event + KeyRing حقيقي في دليل مؤقت)،
لا أحداث مصنوعة يدويًا إلا حيث يُختبر الرفض الصريح نفسه:

1. `test_ed25519_rfc8032_vectors` — متجهات المعيار T1/T2 حرفيًا.
2. `test_ed25519_sign_and_verify` (الإلزامي) — إلحاق فعلي، مؤشر sig_type،
   توقيع 64 بايتًا، VERIFIED، عبث → INVALID، سلامة السجل VERIFIED.
3. `test_legacy_hmac_signature_still_verifies` (الإلزامي) — عدم ارتداد
   المسار التاريخي (لا sig_type، HMAC 64 hex، VERIFIED).
4. `test_cannot_verify_ed25519_with_hmac_key` (الإلزامي) — عزل الأنواع
   في الاتجاهين + النوع المجهول → رفض صريح.
5. `test_rotation_from_hmac_to_ed25519_preserves_history` (الإلزامي) —
   الدوران عبر KeyRotation: الحدث التاريخي صحيح تشفيريًا وتصنيفه وفق
   سياسة RETIRED القائمة (UNVERIFIABLE — ليس INVALID وليس VERIFIED)،
   المفاتيح محفوظة وتُعاد تحميلًا بأنواعها وبصماتها، HISTORY يوثق
   KEY_CREATED/KEY_RETIRED، والأحداث الجديدة VERIFIED.

## ٢) الحارس كخدمة (ملفات فقط — لا تشغيل)

- `scripts/sovereign-supervisor.service` — وحدة systemd: مُتحققة بـ
  `systemd-analyze verify` (نظيفة)، مسار Python مطلق، WorkingDirectory
  جذر المستودع، جذر بيانات قابل للكتابة، مستخدم غير جذري بعزل،
  Restart=always (5 ثوانٍ، حد 5/دقيقة).
- `scripts/docker-compose.supervisor.yml` — بديل Compose (YAML سليم —
  تحقق فعلي): خدمتا app/supervisor، الحارس يراقب `http://app:8080`
  بالاسم الداخلي (127.0.0.1 داخل حاوية الحارس لا تشير للتطبيق —
  موثق)، إعادة تشغيل unless-stopped، سجل append-only في حجم دائم.
- `docs/OPERATIONS.md` §10 — التشغيل: **الحارس لا يملك منفذ استماع
  إطلاقًا** (كل المنافذ للتطبيق: 8080 صورة / 8000 محلي)، السجل
  `<جذر البيانات>/supervisor/monitor_log.jsonl`، الدورة 2 ثانية، فشل
  القراءة لا يوقف الحارس، خريطة الوعي كل 60 ثانية.

## ٣) تجهيز النشر (ملفات فقط — لا نشر)

- `Dockerfile` — جاهزية fly.io: مستخدم غير جذري (sovereign، امتياز
  أدنى)، HEALTHCHECK عبر urllib على /health، الرفض المغلق محفوظ،
  المنفذ 8080 كما هو.
- `.dockerignore` — بيانات التشغيل لا تُخبز في الصورة (data/
  وnexus_data/ وlogs/ وcache/ وtemp/ وguardian/data/ وaudit/) فوق
  استثناءات الأسرار القائمة — لا معالجة بحذف طبقة لاحقة.
- `fly.toml` — أُزيل `memory_mb = 256` (مفتاح غير صالح في صيغة fly.toml
  يتعارض مع `memory = '512'` في نفس الكتلة) + وثّقت الأسرار بأوامر
  ينفذها المالك (لا قيم فعلية).
- `docs/DEPLOYMENT_READY.md` — قائمة المراجعة: توليد SOVEREIGN_KEY،
  CORS_ORIGINS بقائمة صريحة (صيغة config.py الفعلية: مفصولة بفواصل)،
  fly secrets، حالة البيانات (لا بيانات في الصورة — قرارات الحجم
  الدائم للمالك)، خطوات النشر، تحقق ما بعد النشر.

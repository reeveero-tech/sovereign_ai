# R-738 — ترسانة البحث والاستدلال + بوابة MCP + المنسّق

**التاريخ:** 2026-10-23 — بأمر المالك: «أريد أن تكون أدوات البحث والتنقيح
والاستنتاج والاستخراج والاستنباط والاستدلال من أقوى أدوات العالم، اجمع
حتى لو استطعت ألف أداة أو أكثر، بكامل الصلاحيات، واجعل هناك من يرتب
عملها حسب احتياج المشروع وهدفه».
**القاعدة:** RED→GREEN حقيقي مُشاهد (المادة ٢) + دفعة ذرية واحدة (المادة ٤).

---

## ١) ما الذي بُني

### أ) أدوات الويب (`backend/web_tools.py` — البندان ٣.٢ و٢.٥)
- **`web.search`** — بحث ويب حي بمزودين: SearXNG ذاتي الاستضافة (الافتراضي
  — بلا مفتاح) أو Tavily سحابي. نتائج مستشهدة بمصادر (title/url/snippet).
- **`web.fetch`** — جلب صفحة وتحويلها لنص، **محروس ضد SSRF**: مخطط
  http/https فقط + تحقق كل قفزة (يشمل التحويلات — لا التفاف عبر 302)
  بحجب كل العناوين الخاصة/الداخلية (IPv4+IPv6) + حد حجم (2MiB) + قائمة
  أنواع + سقف تحويلات.
- **`web.summarize`** — استخلاص عبر عقل المنشور (بلا اختراع).

### ب) محور الاستدلال (`backend/reasoning_tools.py`)
خمس أدوات عبر العقل (بروتوكولا R-736): `reasoning.extract` (استخراج
منظّم نص → JSON)، `reasoning.infer` (استنتاج)، `reasoning.deduce`
(استنباط — فرضيات موسومة)، `reasoning.verify` (تنقيح — حكم مدعوم)،
`reasoning.reason` (استدلال خطوة بخطوة).

### ج) بوابة MCP (`backend/mcp_gateway.py`) — طريق «الألف أداة»
MCP هو معيار الصناعة الذي تتصل به **آلاف خوادم الأدوات** المتاحة علنًا
(بحث، ملفات، قواعد بيانات، GitHub، بريد، تنفيذ كود...). البوابة:
- نقلان: **stdio** (عملية محلية) و**http** (خادم بعيد).
- اكتشاف ديناميكي (`tools/list`) وتسجيل كل أداة في سجل R-729 باسم
  `mcp.<خادم>.<أداة>` — **كل استدعاء بأثر TOOL_INVOKED السيادي**.
- «بكامل الصلاحيات» ضمن الدستور: الاستدعاء بمفتاح المالك (الصلاحية
  العليا في النظام) وكل خطوة موثقة في السجل السيادي — لا صلاحية بلا أثر.

### د) المنسّق (`backend/research_orchestrator.py`) — «من يرتب عملها»
`research.run(goal)`: هدف → **بحث ← قراءة المصادر ← استخراج الحقائق ←
استدلال وتوليف ← تقرير مستشهد بالمصادر**. كل خطوة عبر السجل (أثر
إلزامي لكل استدعاء)، والفشل صادق (أول سبب يُعلن، لا تقرير مختلق).

### هـ) السجل (`backend/tool_registry.py` — تطوير R-729)
`invoke(inputs=...)`: المدخلات وسائط مسماة، والمفاتيح **المعلنة حصرًا**
(مفتاح غير معلن → استدعاء فاشل مُسجل ولا تنفيذ). و`/tools/invoke` يقبل
`inputs` (بعد مفتاح المالك كما هو).

## ٢) الإعدادات (كلها بيد المالك — أسرار المنصة، لا المحادثة)

```
WEB_TOOLS_ENABLED=true            # أدوات الويب — التفعيل قرار تشغيلي
SEARCH_PROVIDER=searxng           # أو tavily
SEARCH_BASE_URL=http://127.0.0.1:8888   # خادم searxng محلي (افتراضي)
# أو السحابي: SEARCH_PROVIDER=tavily + SEARCH_API_KEY=<سر>
RESEARCH_MAX_SOURCES=3

MCP_ENABLED=true                   # بوابة MCP — معطلة افتراضيًا
MCP_SERVERS=[{"name":"fs","transport":"stdio","command":"npx","args":["-y","@modelcontextprotocol/server-filesystem","/data"]}]
# أو خادم بعيد: {"name":"remote","transport":"http","url":"https://...","api_key":"<سر>"}
```

الاستدلال (reasoning.*) يعمل متى فُعل العقل (R-736) — لا إعدادات إضافية.

## ٤) الحدود المعلنة (المادة ٥ — بلا ادعاء)

- **«ألف أداة» صادقة التفسير:** البوابة تفتح منظومة MCP (آلاف الخوادم
  علنًا) بعقد واحد — لكن عدد الأدوات الفعلي في كل لحظة = عدد خوادم MCP
  التي يضبطها المالك ويشغلها. لا نزعم عددًا محددًا.
- **التفعيل الحي بيد المالك** (المادة ١٠): WEB_TOOLS/MCP/SEARCH أسرار
  على Fly + أمر نشر؛ والتحقق الحي بعدها (بحث حي عبر الرابط العام →
  نتائج مستشهدة = معيار إغلاق ٢.٥).
- **تغطية الاختبار وهمية لا حية:** لا مفتاح في يد الوكيل (المادة ٩) —
  العقود محاكاة بدقة، والتحقق الحي عند التفعيل.
- **المنسّق v1 خط بحث واحد** (بحث→قراءة→استخراج→استدلال) بخطوات موثقة؛
  التخطيط الديناميكي الموجه بالعقل (اختيار خطة حسب نوع الهدف) حدّ
  موثق للجولة التالية.
- حارس اليتامى: `tests/helpers/fake_mcp_server.py` موثق كنقطة دخول
  سكربت (تشغيل عملية فرعية في الاختبار) — تعديل موثق لا إعفاء مجلد.

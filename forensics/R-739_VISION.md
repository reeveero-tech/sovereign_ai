# R-739 — البند ٢.٢ (عينان): تحليل الصور عبر مدخل /vision

**التاريخ:** 2026-10-24 — بأمر المالك («ابدأ» — تابع الخارطة، المرشح ٢.٢).
**القاعدة:** RED→GREEN حقيقي مُشاهد (المادة ٢) + دفعة ذرية واحدة (المادة ٤).

---

## ١) ما الذي بُني (ومعيار الإغلاق)

معيار البند في الخارطة: «اختبار: صورة → وصف نصي موثق». المنفذ:

- **`backend/vision_client.py`** — عميل رؤية عبر عقل المنشور بنموذج متعدد
  الوسائط منفصل (`VISION_MODEL` — مثل llava/qwen2.5vl محليًا)، ببروتوكولي
  R-736 نفسهما على أساس OLLAMA_* القائم:
  - **ollama**: POST `{base}/api/chat` — الصورة base64 في
    `messages[].images[]` (عقد Ollama للوسائط).
  - **openai**: POST `{base}/chat/completions` — الصورة data-URL داخل
    `content[].image_url` (عقد OpenAI للوسائط).
- **`backend/app.py`** — نقطتان:
  - `POST /vision`: صورة (multipart) → `{"description": ...}`. حراسة بصدق:
    معطل → **503** بالسبب؛ فشل الخدمة → **502**؛ حجم زائد → **413**؛
    نوع غير صورة → **415**؛ تجاوز المعدل → **429**. لا وصف مختلق أبدًا.
  - `GET /vision/status`: الحالة بلا أي سر (العنوان معقّم — نمط
    /brain/status و/stt/status).
- **حدود صارمة:** قراءة بحد + 1 بايت (10MiB افتراضيًا — لا قراءة
  اعتباطية)، قائمة أنواع صور مسموحة فقط، وحد معدل بحد `/chat` نفسه لكل
  IP مباشر (الرفع باهظ — لا باب مفتوح).
- **مبادئ قائمة محفوظة:** معطل افتراضيًا (لا اتصال ضمني)، fail-closed
  (None لا استثناء)، لا مفتاح ولا محتوى صورة في السجلات (نوع الخطأ فقط).

## ٢) الإعدادات (بيد المالك — أسرار المنصة، لا المحادثة)

```
VISION_ENABLED=true          # التفعيل — قرار تشغيلي
VISION_MODEL=llava           # نموذج رؤية (منفصل عن نموذج المحادثة)
VISION_MAX_IMAGE_BYTES=10485760
# يستخدم أساس العقل نفسه: OLLAMA_BASE_URL + OLLAMA_PROTOCOL + OLLAMA_API_KEY
```

> نمط R-736/R-737: سير النشر لا يمرر هذه المتغيرات — تُضبط مباشرة
> `fly secrets set -a sovereign-ai-k20elq ...` ثم أمر نشر (المادة ١٠).
> التحقق الحي بعده: `/vision/status` ثم صورة فعلية عبر `/vision`.

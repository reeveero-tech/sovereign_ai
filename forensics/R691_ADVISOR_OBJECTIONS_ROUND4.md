# R-691 — إصلاحات اعتراضات المراجع (الجولة ٤): طبقة التقييم والرفع الموثق والفشل البارد

**التاريخ:** 2026-10-19 | **المرجع:** اعتراضات المراجع على تسليم R-690 (d3a06e0) | **الحالة:** منفذة — الموانع الثلاثة عولجت بكود واختبارات RED→GREEN، وتصويبات دقة التقرير منفذة، والأدلة داخل forensics/

## الموانع الثلاثة وعلاجها

### ١) حارس تقييم السيادي السالب لم يُعدّل (عولج بكود + اختبار RED→GREEN)

**المانع:** `if not self.sovereign:` في `_evaluate_sovereign` — الحارس السالب — لم
يشمل العزل؛ فاختبار controller_cycle وحده كان ينجح بينما will/alignment/
directives/get_controller_status تستمر.

**العلاج:** الحارس السالب حُوّل إلى `if not self._use("sovereign"):` —
المكوّن المعزول يُعامل كغير موجود: طبقة التقييم تعود بالمسار الافتراضي
(`no_sovereign_layer`) قبل استخراج أي مرجع منها أو استدعائه.

**المثبت (test_sovereign_quarantine_blocks_evaluation_layer):** عزل السيادي ←
الدورة تعيد `sovereign_eval.decision.reason == "no_sovereign_layer"` (طبقة
التقييم لم تُستدعِ شيئًا) + controller_cycle صفر من مرحلة القرار + الدورة
تكتمل. RED عند الأب: «طبقة التقييم لم تُغلق بالعزل: {'will': {'will_strengt…»
(بيانات تقييم حقيقية عادت).

**معيار إثبات موثق:** كائنات الطبقات (will/alignment/directives/controller)
مشتركة — مكونات أخرى قد تستدعيها داخليًا (تُمنع تلك الاستدعاءات عند عزل
مكوناتها بحواجزها الخاصة)؛ هذا الاختبار يثبت مرحلتي التقييم والقرار تحديدًا
كما طلبه المراجع (تتبع الاستدعاءات بالمكدس أثناء التنقيح أكد أن مواقع
الاستدعاء داخل مراحل أخرى تأتي من مكونات أخرى عبر كائنات مشتركة).

### ٢) الرفع الموثق لا يزيل عزل الاحتياط (عولج بكود + اختبارين RED→GREEN)

**المانع:** الاتحاد `file_components | fallback_quarantined` يُبقي عزل الاحتياط
غالبًا حتى بعد رفع موثق لاحق.

**العلاج:** أحداث الحالة الفعالة تُعالَج **مرتبة زمنيًا** عبر المصدرين: الملف
(عزل+رفع نافذان) + عزل الاحتياط فقط (الرفع الفاشل مستبعد من التنفيذ — ج3).
الترتيب الزمني يسمح للرفع الموثق اللاحق بإنهاء عزل سابق فشل توثيقه في
الاحتياط. كما أُزيل اتحاد `| local_fallback` المتبقي من مسار الملف الموجود في
المدخل (القراءة تدمج الاحتياط داخليًا — والاتحاد كان يعيد العزل المنهي).

**المثبت (اختباران):** (أ) داخل العملية: عزل يفشل توثيقه (الملف 444) ← إصلاح
القناة ← رفع موثق ينجح ← الطلب يعيد 200 — بلا clear_fallback في الاختبار.
(ب) عبر سيناريو عملية منفصلة: نفس التسلسل — الحالة النهائية بلا المكوّن.
RED عند الأب: «الرفع الموثق لم ينهِ عزل الاحتياط السابق — أعيد 503» و
«['nexus']».

### ٣) الفشل البارد سماح داخلي + الاختفاء يُقرأ فراغًا (عولج بكود + اختبارين RED→GREEN)

**المانع:** `_quarantine_last_known` يبدأ فارغًا — فشل القراءة قبل أول قراءة
ناجحة = «لا عزل»؛ و`read_entries()` يعامل غياب الملف كمجموعة فارغة فلا يمر
عبر معالجة OSError.

**العلاج — تمييز «لا عزل أثبتته قراءة ناجحة» عن «تعذر إثبات الحالة»:**
- الحالة الثلاثية في المنسق: `_quarantine_proven` / `_quarantine_unknown` /
  `_quarantine_last_known`. القراءة الناجحة تُثبت وتحدّث. تعذر الإثبات
  (قراءة فاشلة أو **غياب ملف** — الغياب يُرفع كـFileNotFoundError صراحة لا
  يُقرأ فراغًا): إن أُثبت شيء سابقًا ← آخر حالة معروفة؛ وإلا ← **مجهول** ←
  كل استدعاء مكوّن يُمنع في الدورة (لا إذنًا صامتًا) والدورة تكتمل بمنطق
  المنسق الذاتي.
- المثبت (test_cold_read_failure_is_not_internal_allow): منسق بارد (لا إثبات
  سابق — محاكاة عملية جديدة) + سجل بعزل موثق + قراءة معطلة ← الدورة: التنبؤ
  صفر استدعاء والدورة تكتمل. RED عند الأب: «الحالة المجهولة تحولت إذنًا —
  استُدعي 3 مرة».
- المثبت (test_file_deletion_after_proven_keeps_orchestrator_quarantine):
  دورة إثبات (قراءة ناجحة) ← حذف الملف ← دورة تالية: العزل المثبت يبقى
  مفروضًا. RED عند الأب: «اختفاء الملف أسقط عزلًا مثبتًا داخل المنسق —
  استُدعي 3 مرة».
